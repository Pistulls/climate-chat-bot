# 02. Ingestion

Load the 29 source PDFs in [sources/](../../sources/index.md) into the `sources` vector index, so the Facts LLM can retrieve passages and cite them. Along the way, settle the embedding model that Design.md left provisional. This plan covers a local Python command-line tool, a retrieval evaluation, and loading the dev and prod indexes. The `/api/chat` service is plan 03.

Decisions made while writing this plan are in [Plan.md](../Plan.md#02-ingestion).

## Status

Phases 0–4 are done, and Phase 5 is done for **dev** (results below). Phase 1 built the package skeleton, `config.py` and the embeddings client; Phase 2 added `sources/manifest.toml` and its loader; Phase 3 extracts and chunks the corpus into 1,811 chunks; Phase 4 embedded them with both candidates and chose **`openai/text-embedding-3-small`**; Phase 5 loaded the dev `sources` index and checked it against the in-memory search. 150 unit tests pass and ruff is clean. **Prod** waits for this branch to merge: CI then resizes prod's indexes to 1536-d, and `load --env prod` can run (step 5.5).

**Experiments (since removed from the repo):** two side experiments tested embedding single facts instead of chunks: facts hand-written for #03, then facts extracted by Claude Haiku from four sources and searched across the corpus. Judged by one LLM judge for both methods, chunks won item by item (the top result answered 81% of 68 myths, against 38% for facts), and facts were only slightly ahead when both filled the same context (85% vs 81% in ~450 tokens). Chunks stay the retrieval unit.

  - Dimension and count checks, and a token counter.
  - The ingest key comes from `.env` first, then SSM.
- **Smoke test** with the real ingest key:
  - **Both candidates work** and return 4096-d (Qwen3) and 1536-d (`text-embedding-3-small`) vectors.
  - **Both ranked the right passage first** for "Solar is pointless because it doesn't generate at night": cosine 0.66 against 0.20 for Qwen3, 0.59 against 0.14 for the OpenAI model.
- **Latency finding.** Qwen3 is slow and erratic on OpenRouter:

  | | Single query | Batch of 64 |
  |---|---|---|
  | `qwen/qwen3-embedding-8b` | **0.6–30 s** | 6.6 s |
  | `openai/text-embedding-3-small` | 0.3–0.5 s | 1.4 s |

  - This doesn't matter for ingestion. It does matter for the service, which embeds every incoming claim inside a 4–6 s reply budget, so step 4.3 adds latency to the bake-off.

## Phase 3 results

`uv run python -m climate_chat.ingest extract`, then `... chunk`, write `build/text/<id>.jsonl` and `build/chunks/<id>.jsonl`. Extracting all 28 sources takes about 3 minutes, most of it #22 and #19; chunking takes seconds. `--source <id>` (repeatable) limits either stage.

**Result: 1,811 chunks, ~799k tokens** including overlap, every chunk 500 tokens or under. That's fewer than Phase 0's 2,300–2,500 estimate because reference lists and number-only tables are gone.

**Extraction problems found on the real PDFs, and their fixes:**

| Problem | Seen in | Fix |
|---|---|---|
| **Words glued together** ("Manydifferentsetsof…"): pdfplumber's default 3 pt word gap is too wide for tightly set journals. #22 lost two-thirds of its word breaks | #04, #11–#15, #17, #21, #22 | A gap relative to font size, `x_tolerance_ratio=0.15`. No over-splitting found; the remaining 1–2 letter tokens are acronyms |
| **Two-column pages read straight across**, interleaving the columns line by line | Most journal papers, #05, #06, #24 | Column detection: a vertical gutter that at most 25% of text rows cross, with prose (≥ 4.5 words per line) on at least one side. Rows spanning the gutter split the page into bands, so titles and full-width figures stay in place; columns are read left then right, recursively for three columns |
| **Tables mistaken for columns** | #23 | The prose test: table cells are short on both sides, so they're never split |
| **Narrow sidebars** read first, so the "Acknowledgments" heading in GRL's sidebar cut the paper's conclusion | #12 | A left column under half the width of the right one is read after it |
| **Subscripts on their own line** ("CO" then "2") | Copernicus journals | `y_tolerance=5` (pdfplumber's default is 3) keeps them on the line: "CO2", "CH4", "N2O" |
| **Reference lists kept**: the heading shares a line with the other column, or the year is lines away from the author | #04, #11, #12, #15, #17 | Column reading puts headings on their own line. Reference pages are recognised by author patterns (`Collins, M.,` and Vancouver `Poland GA,`), DOIs and URLs, ignoring bare list numbers |
| **Running footers moved mid-page** by column reading | #04, #11 | A worded line repeated at page edges is dropped wherever it appears; bare page numbers only at the edges |
| **Repeated table headers** ("CAP (MW) 2016 2017 …") looked like running headers | #23 | Lines with four or more standalone numbers never count as boilerplate |
| **Chart axis ticks** as runs of single numbers | #19, #22 | Only evenly spaced runs (0, 20, 40, 60) are dropped; other single-number lines are table cells and stay |
| **Contents pages** of dot leaders | #22 | Dot leaders removed |
| **Number grids without labels** and scrambled chart text | #23 (240 chunks), #01, #03, #11, #22 | Chunks where under 20% of tokens are words are skipped (281 in all). #23 keeps 52 chunks with labels |

- **#12's Wiley download stamp** (Phase 2) is rotated text, so the upright-only filter already drops it. No chunk contains it.
- **Scan warnings** now fire only for little text over an image: 14 pages, all covers, photos or full-page figures. Still no scanned PDFs.
- **Known limits**, each small enough to leave:
  - #05's three-column "key messages" boxes sit above single-column text, which the gutter test can't separate, so they stay interleaved. The text below each box repeats its points.
  - Figure labels drawn over images can come out scrambled (e.g. one line in `12-0014`).
  - 19 chunks in #04 and #11 keep a journal footer line where the page footer was read as one full-width line.
  - #03 sets some subscripts lower than 5 pt, so 8 chunks have "CO" and "2" on separate lines.
- **Tests** are in `tests/ingest/`: synthetic page text for the cleaning rules, synthetic word boxes for column detection, and a word-count tokenizer for chunking, so no PDFs or network are needed.

## Phase 4 results

**Winner: `openai/text-embedding-3-small` (1536-d).**

| Model | recall@5 | MRR | Query latency p50 / p95 | Embedding the corpus |
|---|---|---|---|---|
| `openai/text-embedding-3-small` | **20/20** | 0.94 | **0.37 s / 0.70 s** | 823k tokens, 58 s |
| `qwen/qwen3-embedding-8b` | 19/20 | 0.93 | 3.68 s / 12.2 s | 893k tokens, 329 s |

- **Qwen3 is out on latency** (p95 over the 2 s limit), whatever its recall. Its one miss was "no warming since 1998", where its first expected chunk came 12th.
- **Recall@5 of 1.0 beats the 0.8 target**, so chunking needs no tuning. The measure is lenient, though: most myths list several acceptable sources. MRR (0.94) is the stricter signal, and the top hit is from an expected source for 18 of 20 myths.
- **Each chunk is embedded with its source title as a first line**, because many chunks never name their source. That adds ~36k tokens per model, and the cache hash covers the title.
- **Cost:** about $0.03 for both models together, as planned.
- **Files:** `eval/retrieval_myths.toml` (20 myths, 4 per CARDS category, plus the energy topics; expected sources were checked against chunk text), `ingest/embed.py`, `ingest/evaluate.py`, and the CLI stages `embed` and `evaluate --in-memory`. The report is `build/reports/embedding-eval.md`.
- **Config switched:** `embedding_dimension = 1536` and `models.embedding` in both `envs/*.tfvars`, and `MODEL_EMBEDDING` / `EMBEDDING_DIMENSION` in `.env.example` and `.env`. Design.md records the result.
- **Applied to dev** on 2026-11-23: both empty indexes replaced (2 added, 2 destroyed), now 1536-d cosine; a follow-up plan shows no changes. **Prod** is replaced by CI when this merges to main, along with the Lambda's `MODEL_EMBEDDING` and `EMBEDDING_DIMENSION`.

## Phase 5 results (dev)

- **`vectors.py`** (shared with plan 03): `VectorIndex` with `keys()` (the `list_vectors` paginator), `put()` and `delete()` in batches of 500, `query()` with metadata, distance and an optional filter, and `dimension()`. AWS clients come from `Settings.aws_client()`, which uses `AWS_PROFILE` from `.env` (boto3 itself only reads the process environment).
- **`ingest/load.py`:** per-chunk records with the metadata from step 5.1, checked against the embedding cache (a missing or stale vector stops the load). `citation_url` adds `#page=N` only where the source URL is itself a PDF; landing pages and snapshots keep the plain URL.
- **Idempotent:** a load lists the index's keys, writes each source's chunks, then deletes that source's keys it didn't write. Writes come before deletes, so a failed run never leaves a source short. A full load (no `--source`) also deletes keys of sources that are no longer ingested.
- **`load --env dev`:** 1,811 vectors in 17 s. Running `--dry-run` again afterwards shows nothing new and nothing to delete. The load refuses to run if the index's dimension doesn't match the model's.
- **`evaluate --env dev`** queries the live index and the in-memory search with the same query vectors: both 20/20 recall@5 and MRR 0.94. The top 5 sets are the same for all 20 myths; one myth has two results in swapped order. Report: `build/reports/index-eval-dev.md`.
- **Filter check:** `{"licence": {"$ne": "non-commercial"}}` works. For "renewables are more expensive", it swaps the IRENA (#22) chunks for Ember (#24).

## Pipeline

```
manifest.toml ─► extract ─► chunk ─► embed ─► load ─► eval
 (29 sources)    (PDF→text   (~500-token   (OpenRouter,   (PutVectors,     (20 myths,
                  per page)   chunks with    ingest key,    500 per call;    recall@5
                              page numbers)  cached)        stale keys       against the
                                                            deleted)         live index)
```

Each stage writes to a gitignored `build/` folder, so stages can be re-run on their own, and a re-load never pays for embeddings twice.

## Target layout

```
pyproject.toml              # uv project, Python 3.14 (matches the Lambda)
src/climate_chat/
  config.py                 # env names, model ids, SSM parameter names; reads .env
  openrouter.py             # embeddings client (OpenAI SDK), retries, provider routing
  vectors.py                # S3 Vectors put / list / delete / query helpers
  ingest/
    manifest.py             # load + validate sources/manifest.toml (tomllib)
    extract.py              # PDF -> per-page text, cleaning
    chunk.py                # pages -> chunks with page ranges

    evaluate.py             # retrieval eval (in-memory or against the index)
    __main__.py             # CLI: python -m climate_chat.ingest <stage> ...

tests/ingest/               # unit tests, no network (shared fakes in tests/fakes.py)
build/                      # gitignored: text/, chunks/, embeddings/, reports/
```

The embeddings client and vector helpers sit outside `ingest/` because the service (plan 03) uses the same embedding model and index.

### Phase 1: Project skeleton

- [x] 1.1 `pyproject.toml` (uv, Python 3.14), `src/` layout, `ruff`, `pytest`. Add `build/` and `.venv/` to `.gitignore`.
- [x] 1.2 `config.py`: reads `.env` locally (`APP_ENV`, `VECTOR_BUCKET`, `SOURCES_INDEX`, `MODEL_EMBEDDING`, `EMBEDDING_DIMENSION`). `--env prod` swaps in `climate-chat-prod-vectors`.
- [x] 1.3 `openrouter.py`, the embeddings client:

### Phase 3: Extract and chunk

- [x] 3.1 `extract.py` uses **pdfplumber**, keeping upright characters only. It produces one text record per page, `build/text/<id>.jsonl` with `{page, text}`. Cleaning:
  - Strip leftover `(cid:n)` markers.
  - Join hyphenated line breaks, normalise whitespace and ligatures (`ﬁ` → `fi`).
  - Drop running headers and footers: lines repeated on more than 30% of pages.
  - Drop the **references/bibliography** and acknowledgements sections. They match many queries and answer none.
  - Warn on pages with fewer than 30 words that aren't figure pages, so scanned pages show up.
- [x] 3.2 `chunk.py`:
  - Splits on headings and paragraphs, with chunks of about **500 tokens** and **80 tokens of overlap**, counted with `tiktoken` `cl100k_base`. That's close enough for both models.
  - Never splits inside a table row, and keeps a table's caption with the table.
  - Each chunk records `page_start` and `page_end`.
  - Chunks under 40 tokens are merged into a neighbour.
  - The output is `build/chunks/<id>.jsonl`.
- [x] 3.3 Chunk ids are **`<source_id>-<chunk_no:04d>`**, e.g. `05-0042`, numbered from 1. They're stable for a given extraction, and readable in citations and logs.
- [x] 3.4 Unit tests on small fixture text, with no PDFs: header and footer removal, reference stripping, overlap, page ranges, table rows kept whole, ids.

### Phase 4: Embed and choose the model

Design.md: "embed the corpus with both … then test retrieval with ~20 known myths. Keep the winner."

- [x] 4.1 `eval/retrieval_myths.toml`: 20 claims, written as the neutral one-sentence form the Classify LLM produces. Each one lists the sources that should answer it. They cover the CARDS categories and the energy topics, for example:
  - "Solar is pointless because it doesn't generate at night" → 19, 20, 24
  - "The climate has always changed, so current warming is natural" → 01, 02, 03
  - "Scientists don't agree on climate change" → 13, 14
  - "Climate models have failed to predict warming" → 12
  - "CO2 is a tiny fraction of the atmosphere so it can't matter" → 03, 09
  - "Renewables are more expensive than fossil fuels" → 22
  - "Electric cars aren't cleaner because batteries are so dirty and expensive" → 19, 20, 21
  - "There's been no warming since 1998" → 04, 06, 07, 08

  The other 12 are written in this step. The file is committed, and plan 03 reuses it as a regression test.
- [x] 4.2 `embed.py` embeds every chunk with **both** candidate models. It caches vectors by `sha256(model + text)` in `build/embeddings/<model>/`, so re-runs and re-loads cost nothing.
  - The chunks total ~799k tokens per model (Phase 3), so about $0.01 for Qwen3 and $0.02 for `text-embedding-3-small`.
  - Plain files, no local vector database. Exact brute-force search over a few thousand rows takes milliseconds, and gives a clean baseline to compare S3 Vectors against in 5.4:

    ```
    build/embeddings/<model, "/" -> "--">/
      vectors.npy   # float32 matrix, one row per chunk (N × dim); about 49 MB at 4096-d, 18 MB at 1536-d
      rows.jsonl    # row i -> {"chunk_id": "05-0042", "hash": "<sha256(model + text)>"}
    ```

    The chunk text and metadata stay in `build/chunks/`, joined on `chunk_id`. The load stage reads the winner's `vectors.npy` straight into `PutVectors`.
- [x] 4.3 `evaluate.py --in-memory` runs the comparison locally with numpy cosine similarity. It doesn't touch S3 Vectors, so the 1536-d model needs no second index. For each model, the report covers:
  - **recall@5:** the share of myths with at least one expected source in the top 5 chunks.
  - **MRR**, and the source of the top hit for each myth.
  - **Query latency, p50 and p95** over the 20 myth embeddings. This runs at request time in the service, so it counts.

  The report goes to `build/reports/embedding-eval.md`.
- [x] 4.4 **Pick the winner.** A model whose **p95 query latency is over 2 s** is out, because it would eat the service's reply budget. Of the rest, the higher recall@5 wins. On a tie within one myth, take the cheaper and smaller `text-embedding-3-small`: a 1536-d index is about 2.7× smaller, so queries cost less too.
  - If Qwen3 retrieves clearly better but fails on latency, the options are a provider pin (OpenRouter `provider.order`), a timeout with a fallback, or accepting `text-embedding-3-small`. The choice is yours. A fallback model doesn't work for embeddings, because the index is built with one model (Design.md).
  - If it's `text-embedding-3-small`, set `embedding_dimension = 1536` and `models.embedding` in both `envs/*.tfvars`, and `EMBEDDING_DIMENSION` / `MODEL_EMBEDDING` in `.env.example` and `.env`. Applying that replaces both empty indexes in dev and prod, using the usual plan, breakdown and Continue/Stop before `terraform apply`. The response cache is empty too, so nothing is lost.
  - Record the result and the scores in Design.md, and remove "provisional" from it.
- [x] 4.5 **Target: recall@5 of at least 0.8** (16 of the 20 myths). If neither model reaches it, tune chunking first (size, overlap, the reference-stripping rules) before changing models.
