# 02. Ingestion

Load the 29 source PDFs in [sources/](../../sources/index.md) into the `sources` vector index, so the Facts LLM can retrieve passages and cite them. Along the way, settle the embedding model that Design.md left provisional. This plan covers a local Python command-line tool, a retrieval evaluation, and loading the dev and prod indexes. The `/api/chat` service is plan 03.

Decisions made while writing this plan are in [Plan.md](../Plan.md#02-ingestion).

## Status

Phase 0 is done (results below). Nothing has been built or ingested yet.

## Pipeline

```
manifest.toml ─► extract ─► chunk ─► embed ─► load ─► eval
 (29 sources)    (PDF→text   (~500-token   (OpenRouter,   (PutVectors,     (20 myths,
                  per page)   chunks with    ingest key,    500 per call;    recall@5
                              page numbers)  cached)        stale keys       against the
                                                            deleted)         live index)
```

Each stage writes to a gitignored `build/` folder, so stages can be re-run on their own, and a re-load never pays for embeddings twice.

## Target layout

```
pyproject.toml              # uv project, Python 3.14 (matches the Lambda)
src/climate_chat/
  config.py                 # env names, model ids, SSM parameter names; reads .env
  openrouter.py             # embeddings client (OpenAI SDK), retries, provider routing
  vectors.py                # S3 Vectors put / list / delete / query helpers
  ingest/
    manifest.py             # load + validate sources/manifest.toml (tomllib)
    extract.py              # PDF -> per-page text, cleaning
    chunk.py                # pages -> chunks with page ranges
    embed.py                # chunks -> vectors, with a content-hash cache
    load.py                 # vectors -> S3 Vectors, removing stale keys
    evaluate.py             # retrieval eval (in-memory or against the index)
    __main__.py             # CLI: python -m climate_chat.ingest <stage> ...
sources/manifest.toml       # machine-readable copy of sources/index.md (committed)
eval/retrieval_myths.toml   # 20 myths + expected sources (committed, reused by plan 03)
tests/ingest/               # unit tests, no network
build/                      # gitignored: text/, chunks/, embeddings/, reports/
```

The embeddings client and vector helpers sit outside `ingest/` because the service (plan 03) uses the same embedding model and index.

## Steps

### Phase 0: Measure and decide tooling

- [x] 0.1 **Measure the corpus.** Record the page count, the extractable words and the pages with no text (scanned) for each PDF, in `build/reports/corpus.md`. This replaces the ~1M-token estimate in Design.md, and flags any PDF that needs OCR. The largest are #19 IEA (295 pages), #22 IRENA (216 pages, 51 MB) and #24 Ember (119 pages).
- [x] 0.2 **Choose a PDF extractor** by trying `pypdf` (BSD) and `pdfplumber` (MIT) on four representative PDFs:
  - #02 IPCC SPM (dense prose with figures)
  - #22 IRENA costs (tables)
  - #23 IRENA capacity statistics (pure tables)
  - #27 EIA page snapshot (a web page printed to PDF)

  Pick whichever keeps the numbers in tables legible. Rule out AGPL tools (PyMuPDF), because this is a public repo. Docling is the fallback if neither handles the tables, at the cost of a heavy dependency on torch.
- [x] 0.3 **Vet the dependencies** (`openai`, `boto3`, the extractor, `tiktoken`, `numpy`, `pytest`, `ruff`): licence, maintenance, pinned versions. `uv lock` commits the exact tree.
- [x] 0.4 Check the S3 Vectors limits the loader relies on. See the table in Phase 0 results: ENHANCED indexes, 500 vectors per write, no `ListVectors` prefix filter.

### Phase 1: Project skeleton

- [ ] 1.1 `pyproject.toml` (uv, Python 3.14), `src/` layout, `ruff`, `pytest`. Add `build/` and `.venv/` to `.gitignore`.
- [ ] 1.2 `config.py`: reads `.env` locally (`APP_ENV`, `VECTOR_BUCKET`, `SOURCES_INDEX`, `MODEL_EMBEDDING`, `EMBEDDING_DIMENSION`). `--env prod` swaps in `climate-chat-prod-vectors`.
- [ ] 1.3 `openrouter.py`, the embeddings client:
  - OpenAI SDK pointed at `https://openrouter.ai/api/v1`, calling `embeddings.create(model, input=[...])` in batches of 64.
  - Key from `INGEST_OPENROUTER_API_KEY`. If it isn't set, read SSM `/climate-chat/ingest/openrouter-api-key` with your AWS credentials.
  - Provider routing `{"data_collection": "deny"}`.
  - Retries with backoff on 429/5xx. A 402 (credit cap reached) fails fast with a clear message.
  - Checks every returned vector has `EMBEDDING_DIMENSION` values.
  - Asymmetric inputs: documents are embedded as they are, and queries get the model's instruction prefix (Qwen3: `Instruct: Given a climate-sceptic claim, retrieve passages with evidence about it\nQuery: …`). The service will use the same helper.

### Phase 2: Manifest

- [ ] 2.1 `sources/manifest.toml`, one entry per source:

  ```toml
  [[source]]
  id = "05"
  file = "05-wmo-state-of-global-climate-2025.pdf"
  title = "WMO State of the Global Climate 2025"
  url = "https://library.wmo.int/idurl/4/69807"
  type = "annual_report"     # assessment | annual_report | data | paper | consensus | method | taxonomy | energy
  published = 2026
  snapshot = false            # true for web pages captured as PDF
  # captured = 2026-11-22     # date, for snapshots only (TOML has no null)
  licence = "open"            # open | cc-by | cc-by-nc | non-commercial | gov
  ingest = true
  ```

  `sources/index.md` stays the human-readable list. A test checks the two agree on ids and file names.
- [ ] 2.2 Mark the known problems:
  - **#10 NASA sea level:** a news hub rather than the data page, so set `ingest: false` until a better source is found.
  - **#21–#23 (non-commercial reuse):** set `licence: non-commercial` and ingest them. The licence is a filterable key, so they can be excluded at query time if launch terms need it. The decision itself stays open (see Plan.md).

### Phase 3: Extract and chunk

- [ ] 3.1 `extract.py` uses **pdfplumber**, keeping upright characters only. It produces one text record per page, `build/text/<id>.jsonl` with `{page, text}`. Cleaning:
  - Strip leftover `(cid:n)` markers.
  - Join hyphenated line breaks, normalise whitespace and ligatures (`ﬁ` → `fi`).
  - Drop running headers and footers: lines repeated on more than 30% of pages.
  - Drop the **references/bibliography** and acknowledgements sections. They match many queries and answer none.
  - Warn on pages with fewer than 30 words that aren't figure pages, so scanned pages show up.
- [ ] 3.2 `chunk.py`:
  - Splits on headings and paragraphs, with chunks of about **500 tokens** and **80 tokens of overlap**, counted with `tiktoken` `cl100k_base`. That's close enough for both models.
  - Never splits inside a table row, and keeps a table's caption with the table.
  - Each chunk records `page_start` and `page_end`.
  - Chunks under 40 tokens are merged into a neighbour.
  - The output is `build/chunks/<id>.jsonl`.
- [ ] 3.3 Chunk ids are **`<source_id>-<chunk_no:04d>`**, e.g. `05-0042`. They're stable for a given extraction, and readable in citations and logs.
- [ ] 3.4 Unit tests on small fixture text, with no PDFs: header and footer removal, reference stripping, overlap, page ranges, table rows kept whole, ids.

### Phase 4: Embed and choose the model

Design.md: "embed the corpus with both … then test retrieval with ~20 known myths. Keep the winner."

- [ ] 4.1 `eval/retrieval_myths.toml`: 20 claims, written as the neutral one-sentence form the Classify LLM produces. Each one lists the sources that should answer it. They cover the CARDS categories and the energy topics, for example:
  - "Solar is pointless because it doesn't generate at night" → 19, 20, 24
  - "The climate has always changed, so current warming is natural" → 01, 02, 03
  - "Scientists don't agree on climate change" → 13, 14
  - "Climate models have failed to predict warming" → 12
  - "CO2 is a tiny fraction of the atmosphere so it can't matter" → 03, 09
  - "Renewables are more expensive than fossil fuels" → 22
  - "Electric cars aren't cleaner because batteries are so dirty and expensive" → 19, 20, 21
  - "There's been no warming since 1998" → 04, 06, 07, 08

  The other 12 are written in this step. The file is committed, and plan 03 reuses it as a regression test.
- [ ] 4.2 `embed.py` embeds every chunk with **both** candidate models. It caches vectors by `sha256(model + text)` in `build/embeddings/<model>/`, so re-runs and re-loads cost nothing.
  - Expected cost is about 1M tokens per model: ~$0.01 for Qwen3 and ~$0.02 for `text-embedding-3-small`. Step 0.1 gives the real figure.
  - Plain files, no local vector database. Exact brute-force search over a few thousand rows takes milliseconds, and gives a clean baseline to compare S3 Vectors against in 5.4:

    ```
    build/embeddings/<model, "/" -> "--">/
      vectors.npy   # float32 matrix, one row per chunk (N × dim); about 49 MB at 4096-d, 18 MB at 1536-d
      rows.jsonl    # row i -> {"chunk_id": "05-0042", "hash": "<sha256(model + text)>"}
    ```

    The chunk text and metadata stay in `build/chunks/`, joined on `chunk_id`. The load stage reads the winner's `vectors.npy` straight into `PutVectors`.
- [ ] 4.3 `evaluate.py --in-memory` runs the comparison locally with numpy cosine similarity. It doesn't touch S3 Vectors, so the 1536-d model needs no second index. For each model, the report covers:
  - **recall@5:** the share of myths with at least one expected source in the top 5 chunks.
  - **MRR**, and the source of the top hit for each myth.

  The report goes to `build/reports/embedding-eval.md`.
- [ ] 4.4 **Pick the winner.** The higher recall@5 wins. On a tie within one myth, take the cheaper and smaller `text-embedding-3-small`: a 1536-d index is about 2.7× smaller, so queries cost less too.
  - If it's `text-embedding-3-small`, set `embedding_dimension = 1536` and `models.embedding` in both `envs/*.tfvars`, and `EMBEDDING_DIMENSION` / `MODEL_EMBEDDING` in `.env.example` and `.env`. Applying that replaces both empty indexes in dev and prod, using the usual plan, breakdown and Continue/Stop before `terraform apply`. The response cache is empty too, so nothing is lost.
  - Record the result and the scores in Design.md, and remove "provisional" from it.
- [ ] 4.5 **Target: recall@5 of at least 0.8** (16 of the 20 myths). If neither model reaches it, tune chunking first (size, overlap, the reference-stripping rules) before changing models.

### Phase 5: Load

- [ ] 5.1 `load.py --env <dev|prod> [--source <id>]` writes up to 500 vectors per `PutVectors` call. Per chunk:

  | Key | Filterable | Example |
  |---|---|---|
  | vector key | n/a | `05-0042` |
  | `source_id` | yes | `05` |
  | `type` | yes | `annual_report` |
  | `published` | yes | `2026` |
  | `licence` | yes | `open` |
  | `page_start`, `page_end` | yes | `12`, `13` |
  | `title` | no | `WMO State of the Global Climate 2025` |
  | `citation_url` | no | `<url>#page=12` for PDFs, or the plain page URL for snapshots |
  | `chunk_text` | no | the chunk (~2 KB, well under the 40 KB limit) |

- [ ] 5.2 **Idempotent re-loads.** Before writing a source, list the index's keys with `ListVectors` and keep those starting with `<id>-`. After writing, delete any old key that the new run didn't write (`DeleteVectors`). At about 3,000 vectors, a full listing is a few paginated calls. No local state file is needed.
- [ ] 5.3 **`--dry-run`** prints the counts per source (chunks, new keys, keys to delete) and writes nothing.
- [ ] 5.4 Load **dev**, then run `evaluate.py --env dev` against the live index with `QueryVectors` (topK 5, with metadata). It should reproduce the in-memory recall@5; a different result points to a loading bug.
- [ ] 5.5 Load **prod** with the same command and `--env prod`, then run the same evaluation against prod.

### Phase 6: Document and hand over

- [ ] 6.1 Add an "Ingestion" section to the root README: setup (`uv sync`), the stages, `--env`, `--dry-run`, and re-capturing snapshots.

## Cost

| Item | Estimate |
|---|---|
| Embeddings, both models for the bake-off | ~$0.03 once (about 1M tokens per model) |
| Embeddings, re-ingest of one source | Under $0.001. Unchanged chunks come from the cache |
| S3 Vectors storage | ~3,000 vectors × (16 KB vector + ~3 KB metadata) ≈ 60 MB per env, which is well under $0.01/month |
| S3 Vectors writes and queries | Fractions of a cent for each full load and evaluation run |
| Eval queries (20 myths per run) | 20 query embeddings plus 20 `QueryVectors`, under $0.001 |

## Notes for plan 03 (service)

- Use `openrouter.py` and `vectors.py` from this plan for the claim embedding and the Facts Search. Queries need the same instruction prefix as the evaluation, or retrieval quality drops.
- The citation check compares the answer card's `source_ids` with the retrieved chunk ids (`05-0042`). For citations shown to users, use `title` and `citation_url` from the chunk's metadata.
- `licence` is filterable: add `licence != non-commercial` to the query filter if launch terms require it.
- `eval/retrieval_myths.toml` becomes the service's retrieval regression test.

## Out of scope

- Ingesting the CSV and Excel data behind the data-portal snapshots (#25, #26, #28, #29). The PDFs give the headline figures; structured data lookups would be a later plan.
- Automating snapshot re-capture.
- Running ingestion in CI. It's a rare, manual, local job, using your credentials and the credit-capped `ingest` key.
- OCR. Phase 0.1 shows whether any PDF needs it.
