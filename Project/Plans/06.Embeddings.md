# 06. Embeddings on Amazon Titan V2

Move the claim and chunk embeddings from `openai/text-embedding-3-small` (through OpenRouter) to **Amazon Titan Text Embeddings V2** (`amazon.titan-embed-text-v2:0`), called directly through AWS Bedrock in `eu-west-2`.

The behaviour is specified in [Design.md](../Design.md#models), which is the source of truth. This plan covers how the change gets built, rolled out and checked. Decisions go in [Plan.md](../Plan.md#06-embeddings).

## Status

**Planned.** Design approved 2026-11-24. Phase 1 (the Bedrock client, merge 1) is next.

## Intent

- **Why:** on 2026-11-24 every sceptical claim in prod failed with 502 for over 45 minutes. The OpenRouter account's zero-data-retention (ZDR) setting leaves Azure as the only provider for `text-embedding-3-small`, and Azure was returning "Provider returned error". The service can't fall back, because the indexes are built with that one model. Plan 04's prod round trip is blocked on it.
- **Goals:**
  - Embeddings from Titan V2 on Bedrock, with the Lambda's IAM role: no OpenRouter key, and the claim text stays in AWS in London.
  - Ingestion and the service embed the same way, as now.
  - Prod answers claims again, and plan 04's round trip can finish.
  - **The 12 new UK sources (#30–#41)** from the research doc are ingested in the same run: home efficiency, energy prices, heat pumps, EV running costs, generation costs, the power mix and storage. They fill the heat-pump gap plan 05 found.
- **Non-goals:**
  - Fixing the two myths Titan ranks badly (see [the bake-off](#bake-off-2026-11-24)). They're recorded as a follow-up.
  - A second embedding provider or a fallback model.
  - Changing the chat models, which stay on OpenRouter.
- **Anti-goals (a failure even if it works):**
  - A service and index that use different models or dimensions.
  - A Bedrock error that reaches the user as a 500 instead of the usual 502.
  - Credentials or account details in the repo.

- **Titan's two misses:**
  - "There has been no global warming since 1998": first expected source at rank 10. Its top result is #03, which isn't on that myth's expected list but which prod replies already cite for it.
  - "Petrol and diesel prices are soaring because of climate policies": rank 16, with #19 (IEA EV Outlook) at the top.

## Design

### The client

- **`climate_chat/bedrock.py`: `BedrockEmbeddingClient`**, with the same interface the callers use today: `model`, `dimension`, `tokens_used`, `embed_documents(texts) -> np.ndarray` and `embed_query(text) -> np.ndarray`.
  - One `invoke_model` call per text (Titan V2 takes one input), with the body `{"inputText", "dimensions": <dimension>, "normalize": true}`.
  - Counts `inputTextTokenCount` into `tokens_used`.
  - Checks that the vector length equals `dimension`.
  - `embed_documents` runs 2 workers and keeps the input order.
  - No query prefix: Titan has no instruction format.
  - Any `botocore` error (`ClientError`, `BotoCoreError`) becomes `EmbeddingError`, which the pipeline already turns into 502 `upstream_error`.
- **Two retry profiles**, set on the boto3 client:
  - **Service:** standard mode, 3 attempts, 2 s connect and 5 s read timeouts, so the reply budget holds.
  - **Ingestion:** adaptive mode, 12 attempts, to ride out the token-per-minute throttling.
- **One factory picks the client by model id:** `embedding_client(model, dimension, *, settings, api_key=None, for_ingest=False)` in `climate_chat/embeddings.py`. Ids starting `amazon.` use Bedrock, through `settings.aws_client("bedrock-runtime", ...)`. Anything else uses the existing OpenRouter `EmbeddingClient`, which needs `api_key`. The service (`build_app`) and ingestion (`_client`) both call it, so the bake-off can still compare models.
- **`embed.CANDIDATES`** gains `"amazon.titan-embed-text-v2:0": 1024`. The embedding cache folder becomes `build/embeddings/amazon.titan-embed-text-v2:0`.
- Ingesting with Titan needs AWS credentials (the `.env` profile), not the OpenRouter ingest key.

### Infrastructure

- **`envs/dev.tfvars` and `envs/prod.tfvars`:** `embedding_dimension = 1024` and `models.embedding = "amazon.titan-embed-text-v2:0"`. Changing the dimension replaces both `aws_s3vectors_index` resources, which empties `sources` and `response-cache`.
- **Lambda IAM** (`modules/hosting/lambda.tf`): a new `Embeddings` statement allowing `bedrock:InvokeModel` on `arn:aws:bedrock:<region>::foundation-model/amazon.titan-embed-text-v2:0`, built from the model id variable so a later change follows it.
- The CI role can already create and delete the indexes and update the Lambda's policy and environment. No bootstrap change.

### Rollout (approach A)

1. **Merge 1, code only.** The client, the factory and the tests. Prod still runs `text-embedding-3-small`, so nothing changes.
2. **Dev, locally:** apply the tfvars change to dev (two confirmations), which replaces the dev indexes. Update your `.env` (`MODEL_EMBEDDING`, `EMBEDDING_DIMENSION`). Then embed once (about 2.5 min, $0.08), load dev, and run the live retrieval tests and the reply evaluation.
3. **Merge 2, Terraform.** CI replaces the prod indexes, switches the Lambda's environment and adds the Bedrock permission. Straight away, load prod from the same cached embeddings (no new embedding cost), then run the smoke invoke and `evaluate --env prod`.
4. **Plan 04's round trip** from your browser, which finishes 4.5 there.

### The live retrieval test

`tests/service/test_live_retrieval.py` changes from one test per myth to one test that needs **at least 18 of the 20** myths to find an expected source in the top 5 (`MIN_HITS = 18`, matching plan 02's 0.8 target). It lists every miss in its failure message. The two known misses go in a comment.

## Calls I made (check these)

- **The model id decides the provider** (`amazon.` means Bedrock); no new setting.
- **2 workers for ingestion:** 8 were throttled, and 2 took 148 s for the whole corpus.
- **Service timeouts of 2 s to connect and 5 s to read, with 3 attempts.** Titan answered in under 0.1 s, and a stuck call mustn't use up the Lambda's 30 s.
- **The bake-off script stays out of the repo.** Its results are recorded above. `evaluate --in-memory` can rerun it once Titan is in `CANDIDATES`.
- **Dev is re-ingested before prod,** and prod is loaded from the same embeddings cache, so the corpus is embedded once.
- **The OpenRouter embedding client stays** for the bake-off and as a way back. It's no longer used in prod.

## Global constraints

- Python 3.14, no new runtime dependencies (`boto3` is already in the Lambda). ruff, pytest; unit tests make no network calls, and live tests are marked `live`.
- `MODEL_EMBEDDING` and `EMBEDDING_DIMENSION` come from settings, never hard-coded at call sites. Ingestion, the service and both indexes always use the same model and dimension.
- No secrets, account IDs, profile names or the real domain in committed files.
- You commit and merge. Terraform applies need your two confirmations; CI applies prod on merge.

## Review focus

1. **Throttling during ingestion.** Titan's limit here is 300,000 tokens a minute. Expected: the ingest client uses adaptive retries with 12 attempts and 2 workers, and a full ingest finishes without a `ThrottlingException`. Test: `test_ingest_client_uses_adaptive_retries` (the client config), and the real dev ingest in 2.2.
2. **Bedrock failing during a reply.** Expected: 502 `upstream_error`, never 500, and Classify's cost is still logged. Test: `test_bedrock_error_becomes_embedding_error`, and `test_pipeline_embedding_error_is_502` with an `EmbeddingError`.
3. **A vector of the wrong length** (settings say 1536, Titan gives 1024). Expected: `EmbeddingError` naming both sizes. Test: `test_bedrock_dimension_mismatch`.
4. **Document order with 2 workers.** Expected: row *i* is text *i*. Test: `test_bedrock_documents_keep_order` (a fake that answers out of order).
5. **Loading into an index of the old size.** Expected: `load` refuses with "apply the Terraform change first" (existing check). Covered by the rollout order; checked in 2.2.
