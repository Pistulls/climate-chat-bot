# 01. Infrastructure

Set up the AWS infrastructure from [Design.md](../Design.md) with Terraform. This covers the hosting, data stores, secrets and CI wiring only. The Python service, the ingestion script and the Solid UI are separate plans; this plan deploys a placeholder Lambda and a placeholder `index.html` so the whole path can be tested end to end.

Decisions made while writing this plan are in [Plan.md](../Plan.md#decisions).

## Current AWS setup (from the website repo)

The website repo is separate from this one. Facts this plan relies on:

| Item | Value |
|---|---|
| Account / region | `<account_id>`, `eu-west-2` (London) |
| Local credentials | an admin AWS SSO profile, `AWS_PROFILE=<admin-profile>` (`aws sso login --profile <admin-profile>`) |
| Terraform | `>= 1.10`, AWS provider `~> 6.0`, CI pins Terraform `1.16.5` |
| State bucket | `<state-bucket>` (versioned, encrypted, S3 lockfile). Website keys: `bootstrap/…`, `site/…` |
| Hosted zone | `<domain>` in the website's `bootstrap/` stack, with a CAA record allowing only `amazon.com` |
| Certificate | `*.<domain>` + apex, in `us-east-1`, owned by the website's `bootstrap/` |
| GitHub OIDC provider | `token.actions.githubusercontent.com`, created once by the website's `bootstrap/` |
| Stack pattern | `bootstrap/` (long-lived, applied locally as admin) and `Infrastructure/` (applied by CI on merge to `main`, via an OIDC role that trusts only `main`) |

### Why the sub-domain playbook isn't used as-is

The website's `playbooks/external-repo-subdomain.md` adds a slug to a **shared static distribution**: one S3 bucket, one prefix per slug, a router function, and no SPA fallback. Climate Chat can't use it because it needs:

- an `/api/*` behaviour that sends requests to a Lambda function URL,
- a SPA fallback for the Solid app,
- its own response headers policy (a CSP that allows Cloudflare Turnstile).

So this project gets **its own CloudFront distribution and hosted zone**, as Design.md already says. It borrows these from the playbook: GitHub OIDC trust pinned to immutable repo IDs and `ref:refs/heads/main`, no `environment:` key in workflows, an OAC-locked S3 bucket, and `PriceClass_100`.

The only change in the website repo is **one NS delegation record** (step 3.2).

## Target layout

```
Infrastructure/
  bootstrap/        # long-lived; applied locally as admin; prevent_destroy where it matters
    backend.tf      # key: climate-chat/bootstrap/terraform.tfstate
    versions.tf     # providers: default eu-west-2, alias us_east_1
    dns.tf          # hosted zone climate-chat.<domain> + CAA
    certificates.tf # ACM cert for climate-chat.<domain> (us-east-1), DNS-validated
    github-oidc.tf  # deploy role for this repo (reuses existing OIDC provider)
    ssm.tf          # SecureString parameters (placeholder values only)
    budget.tf       # monthly cost alarm
    outputs.tf
  app/              # applied per env; prod by CI on main, dev locally
    backend.tf      # key: climate-chat/<env>/terraform.tfstate (set with -backend-config)
    versions.tf
    variables.tf    # env, region, domain, model ids, limits
    envs/dev.tfvars
    envs/prod.tfvars
    vectors.tf      # S3 Vectors bucket + response-cache and sources indexes
    dynamodb.tf     # logs + ratelimits tables
    lambda.tf       # function, role, log group, function URL, concurrency
    ui.tf           # UI bucket (prod only)
    cloudfront.tf   # distribution, OACs, functions, policies (prod only)
    dns.tf          # A/AAAA alias records (prod only)
    functions/spa-router.js
    placeholder/    # stub handler.py + index.html
    outputs.tf
```

Tags on every resource: `Project = climate-chat`, `Env = <env>`, `ManagedBy = terraform`.

## Environments

| | `dev` | `prod` |
|---|---|---|
| Data stores (vectors, DynamoDB) | yes | yes |
| Lambda | no. The service runs locally | yes |
| UI bucket, CloudFront, DNS records | no. Vite dev server proxies `/api` to the local service | yes |
| OpenRouter key | `/climate-chat/dev/openrouter-api-key` (and `.env`) | `/climate-chat/prod/openrouter-api-key` |
| Applied by | you, locally | CI on merge to `main` |

Resource names carry the env: `climate-chat-<env>-logs`, `climate-chat-<env>-ratelimits`, and vector bucket `climate-chat-<env>-vectors` with indexes `response-cache` and `sources`. The `ingest` key writes to whichever env's `sources` index the script targets.

## Steps

### Phase 0: Checks before writing any Terraform

- [ ] 0.1 Confirm **S3 Vectors is available in `eu-west-2`**. If not, use the nearest EU region that has it for the vector bucket only (a second provider alias). Lambda calls it cross-region; the latency is small next to the LLM calls.
- [ ] 0.2 Confirm the AWS provider version that has `aws_s3vectors_vector_bucket` and `aws_s3vectors_index`, and pin the minimum (`~> 6.x` with that floor).
- [ ] 0.3 Check the account's **Lambda concurrency quota** (`aws service-quotas get-service-quota --service-code lambda --quota-code L-B99A9384`). AWS needs 10 unreserved, so with a quota of 10 you can't set reserved concurrency at all. If so, request an increase (free) or skip reserved concurrency until it's approved.
- [ ] 0.4 Pick the Lambda Python runtime: the newest `python3.x` that Lambda supports on `arm64` today.
- [ ] 0.5 Get this repo's OIDC subject prefix:

  ```bash
  gh api repos/<owner>/climate-chatter/actions/oidc/customization/sub --jq .sub_claim_prefix
  ```

- [ ] 0.6 Add Terraform ignores to `.gitignore` if they're missing: `.terraform/`, `*.tfplan`, `tfplan`, `*.tfstate*`, `*.local.tfvars`, `*.local.hcl`. Commit `.terraform.lock.hcl`.
- [ ] 0.7 **Keep account details out of the public repo.** The account ID, state bucket, domain, OIDC subject prefix and budget email never appear in committed files:
  - Backend: `terraform init -backend-config=backend.local.hcl`. The file is gitignored and holds `bucket`, `key` and `region`. Commit a `backend.example.hcl` with placeholders.
  - Variables: `<env>.local.tfvars` (gitignored) for `domain_name`, `github_oidc_sub_prefix` and `budget_email`. Commit `example.tfvars`.
  - Account ID: read it with `data "aws_caller_identity"` and never hard-code it.
  - CI: pass the same values as GitHub Actions **variables** (`TF_STATE_BUCKET`, `TF_VAR_domain_name`, …) and write `backend.local.hcl` in the workflow before `init`.
  - Terraform outputs and plan logs in a public repo's Actions runs are publicly visible. Mark outputs that reveal ARNs or name servers `sensitive = true`, or don't output them in CI.

### Phase 1: `Infrastructure/bootstrap/` (local, admin)

- [ ] 1.1 `backend.tf` and `versions.tf`, matching the website's (S3 backend, `use_lockfile = true`, `us_east_1` alias).
- [ ] 1.2 **Hosted zone** `climate-chat.<domain>` with `prevent_destroy`. Add a CAA record (`0 issue "amazon.com"`) so the zone doesn't depend on the parent's. Output `name_servers`.
- [ ] 1.3 **ACM certificate** for `climate-chat.<domain>` in `us-east-1`, with DNS validation records in the new zone and `aws_acm_certificate_validation`. This can only finish after the delegation in 3.2 exists, so apply 1.3 after 3.2, or let `terraform apply` wait for validation.
- [ ] 1.4 **GitHub deploy role** `github-deploy-climate-chat`:
  - Trust: `data "aws_iam_openid_connect_provider"` for the existing provider; `aud = sts.amazonaws.com`; `sub = "<prefix from 0.5>:ref:refs/heads/main"`; 1-hour sessions.
  - Permissions, least privilege, with resource ARNs scoped to `climate-chat-prod-*` names:
    - State: list/read/write `climate-chat/prod/*` in the state bucket only.
    - S3 Vectors, DynamoDB, Lambda, IAM (only roles named `climate-chat-prod-*`, plus `iam:PassRole` on them), CloudWatch Logs, S3 UI bucket, CloudFront (distribution, OAC, function, cache/origin-request/response-headers policies), Route 53 records in the new zone only, ACM read-only, SSM `GetParameter` on the prod parameter ARNs only (for the data sources; no values are read in Terraform).
  - Output the role ARN.
- [ ] 1.5 **SSM SecureString parameters**, placeholder value `CHANGE_ME`, with `lifecycle { ignore_changes = [value] }`:
  - `/climate-chat/prod/openrouter-api-key`
  - `/climate-chat/prod/turnstile-secret-key`
  - `/climate-chat/dev/openrouter-api-key`
  - `/climate-chat/ingest/openrouter-api-key`
- [ ] 1.6 **AWS Budget**: $5/month cost budget filtered on tag `Project = climate-chat`, alerting by email at 80% actual and 100% forecast. The first two budgets are free. The `Project` tag must be activated as a cost allocation tag in Billing (one-off, manual).
- [ ] 1.7 `terraform fmt`, `validate`, `plan` (expected: zone, CAA, cert + validation, role + policy, 4 parameters, budget). Apply after review, following the two-step confirmation in the website's `CODING_STANDARDS.md`.

### Phase 2: Secrets and third-party setup (manual, outside Terraform)

- [ ] 2.1 Create three OpenRouter keys, `prod`, `dev` and `ingest`, each with a credit cap (e.g. $5, $2, $1).
- [ ] 2.2 Create a Cloudflare Turnstile widget in **managed** mode, with hostnames `climate-chat.<domain>` and `localhost`. The site key goes in the UI build config; the secret goes in SSM.
- [ ] 2.3 Set the real values:

  ```bash
  aws ssm put-parameter --name /climate-chat/prod/openrouter-api-key --type SecureString --value "<key>" --overwrite
  ```

  Repeat for the other three. Put the dev key in the gitignored `.env` as well.

### Phase 3: DNS delegation (website repo)

- [ ] 3.1 Read the name servers: `terraform -chdir=Infrastructure/bootstrap output -json name_servers`.
- [ ] 3.2 In the website repo's `Infrastructure/dns.tf`, add an `NS` record `climate-chat.<domain>` with those four values (TTL 3600). Hard-code them with a comment pointing back to this repo: the zone has `prevent_destroy`, so they don't change, and the website's CI role can't read this repo's state. Open a PR; CI applies it on merge.
- [ ] 3.3 Check: `dig NS climate-chat.<domain> +short` returns the four AWS name servers, then the ACM certificate shows `ISSUED`.

### Phase 4: `Infrastructure/app/` data stores (dev first, then prod)

- [ ] 4.1 `backend.tf` with a partial config, initialised per env: `terraform init -backend-config="key=climate-chat/<env>/terraform.tfstate"`. Variables: `env`, `region`, `domain_name`, `subdomain = "climate-chat"`, `create_edge` (false for dev), model IDs, rate limits, `max_comment_chars`.
- [ ] 4.2 **S3 Vectors**: bucket `climate-chat-<env>-vectors`, and two indexes, both `float32`, cosine distance, dimension from `var.embedding_dimension`:
  - `response-cache`: non-filterable metadata key `answer_card`. Filterable by default: `confidence`, `cards_category`.
  - `sources`: non-filterable metadata keys `chunk_text`, `citation_url`. Filterable: `source_id`.
  - The dimension depends on the embedding model (Qwen3-Embedding-8B or `text-embedding-3-small`, still being decided in Design.md). An index can't change dimension, so changing the model means replacing the index (`terraform apply -replace`) and re-ingesting.
- [ ] 4.3 **DynamoDB**, on-demand, SSE with the AWS-owned key, PITR off, deletion protection on for prod:
  - `climate-chat-<env>-logs`: `pk` (S), `sk` (S), TTL attribute `expires_at`. Key design is left to the service plan; a string pk/sk pair keeps it open.
  - `climate-chat-<env>-ratelimits`: `pk` (S, e.g. `ip#<ip>#min#<window>`), TTL attribute `expires_at`.
- [ ] 4.4 Apply **dev**. Check with `aws s3vectors list-indexes --vector-bucket-name climate-chat-dev-vectors` and `aws dynamodb describe-time-to-live`.

### Phase 5: `Infrastructure/app/` compute and edge (prod)

- [ ] 5.1 **Lambda** `climate-chat-prod-api`, `arm64`, runtime from 0.4, 512 MB, 30 s timeout:
  - Code: `placeholder/handler.py` zipped with `archive_file`. It returns `503 {"error":"not deployed"}`. Add `lifecycle { ignore_changes = [filename, source_code_hash] }`, so the service's own deploy (a later plan) owns the code and Terraform owns the config.
  - Env vars: model IDs, limits, table and index names, and SSM parameter **names**. No secret values.
  - Log group `/aws/lambda/climate-chat-prod-api`, 14-day retention.
  - Reserved concurrency `var.reserved_concurrency` (e.g. 5), subject to 0.3.
  - Execution role, least privilege:
    - `s3vectors:QueryVectors`, `GetVectors` on both indexes; `PutVectors` on `response-cache` only.
    - `dynamodb:PutItem` on logs; `UpdateItem`, `GetItem` on ratelimits.
    - `ssm:GetParameter` on the two prod parameter ARNs; `kms:Decrypt` on `alias/aws/ssm` with condition `kms:ViaService = ssm.eu-west-2.amazonaws.com`.
    - Logs write to its own log group.
- [ ] 5.2 **Function URL**, `authorization_type = "AWS_IAM"`, plus resource-based permissions for `cloudfront.amazonaws.com` scoped to the distribution ARN: **both** `lambda:InvokeFunctionUrl` and `lambda:InvokeFunction`. AWS has required both for function URLs since late 2025.
- [ ] 5.3 **UI bucket** `climate-chat-prod-ui-<account_id>`: public access block, OAC-only bucket policy, `s3:ListBucket` for CloudFront so missing keys return 404 rather than 403. Upload `placeholder/index.html` once with `aws_s3_object` and `ignore_changes`. The UI deploy (a later plan) owns the content.
- [ ] 5.4 **CloudFront distribution**, alias `climate-chat.<domain>`, cert from bootstrap (looked up with a data source), `PriceClass_100`, IPv6, TLS 1.2_2021, HTTP/2 and HTTP/3:
  - **Default behaviour, S3 origin** (OAC, origin type `s3`): `CachingOptimized`, compress, and a viewer-request **CloudFront Function `spa-router`** that rewrites paths without a file extension to `/index.html`.
    - Don't use distribution-level custom error responses for the SPA fallback. They apply to every behaviour, so a 403 from `/api/chat` (failed Turnstile check) would come back as `index.html` with a 200.
  - **`/api/*` behaviour, Lambda URL origin** (OAC, origin type `lambda`):
    - All methods allowed; `CachingDisabled`.
    - Custom origin request policy: all viewer headers **except `Host`** (the function URL rejects a foreign Host), all query strings, no cookies, plus **`CloudFront-Viewer-Address`** so the rate limiter sees the real client IP rather than CloudFront's.
  - **Response headers policy**: HSTS, `nosniff`, `frame-options DENY`, referrer policy, and a CSP that allows `https://challenges.cloudflare.com` for script-src and frame-src.
- [ ] 5.5 **Route 53**: A and AAAA aliases for `climate-chat.<domain>` in the project's zone, pointing at the distribution.
- [ ] 5.6 Plan and apply **prod** locally the first time, to catch permission gaps with admin credentials before handing it to CI.

### Phase 6: CI (`.github/workflows/infra.yml`)

- [ ] 6.1 Trigger on push to `main` for `Infrastructure/app/**` and the workflow file, plus `workflow_dispatch`. `concurrency: infra-prod`, not cancelled. `permissions: contents: read, id-token: write`. No `environment:` key.
- [ ] 6.2 Steps: checkout, `configure-aws-credentials` with `vars.AWS_DEPLOY_ROLE_ARN`, `setup-terraform` pinned to `1.16.5`, `init` with the prod backend key, `fmt -check`, `validate`, `plan -var-file=envs/prod.tfvars -out=tfplan`, `apply tfplan`.

- [ ] 6.4 `gh variable set AWS_DEPLOY_ROLE_ARN --repo <owner>/climate-chatter --body "<arn from 1.4>"`.
- [ ] 6.5 Re-run apply through CI with no changes and confirm the plan is empty and the role has enough permissions.

### Phase 7: End-to-end checks

- [ ] 7.1 `curl -sI https://climate-chat.<domain>/` returns `HTTP/2 200` (the placeholder `index.html`).
- [ ] 7.2 `curl -sI https://climate-chat.<domain>/some/route` returns 200 with `index.html` (SPA fallback).

## Notes for later plans

- **POST through OAC to a Lambda URL needs a payload hash.** CloudFront doesn't sign request bodies, so the browser must send `x-amz-content-sha256` (the hex SHA-256 of the body) on every `POST /api/chat`. The Solid app can compute it with `crypto.subtle.digest`. Without it, the request fails with a signature error. The UI plan must include this.
- The service reads the client IP from `CloudFront-Viewer-Address` (`ip:port`), not from `requestContext.http.sourceIp`, which is a CloudFront edge address.
- Lambda code and UI content are deployed by their own workflows (`aws lambda update-function-code`, `aws s3 sync` + invalidation of `/index.html`). Terraform ignores both.
- If the dev env later needs a hosted URL, set `create_edge = true` with alias `dev.climate-chat.<domain>`. That needs a second certificate SAN.
