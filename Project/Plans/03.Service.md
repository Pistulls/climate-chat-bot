# 03. Service (`/api/chat`)

Build the Python service behind `POST /api/chat`, as specified in [Design.md](../Design.md#two-stage-reply-facts-then-tone). It takes a climate-sceptic comment and returns a short, cited, factual reply. The plan ends with the service deployed to the prod Lambda by CI and passing a smoke test, but **not yet public**: real Turnstile tokens only come from the widget, so the first public end-to-end test happens in plan 04 (Solid UI).

Decisions made while writing this plan go in [Plan.md](../Plan.md#03-service).

## Status

**Design, awaiting approval.** Steps are added once the design is approved.

## Intent

The point of the bot is replies that are **correct and traceable**: every fact comes from a retrieved source passage, and code (not the model's good behaviour) enforces that. v1 should be **as simple as possible**: the smallest service that delivers Design.md's pipeline with its safety checks, with no framework, no new dependencies, and nothing that isn't needed before launch.

### Goals

- `POST /api/chat` with Design.md's contract: `{ comment, turnstile_token, platform?, style? }` → `{ reply, citations, fallacy, cached }`.
- The full pipeline: Turnstile → rate limit → length cap → Classify → claim embedding → cache lookup → (on a miss) source search → Facts → citation check → cache write → Reply → reply checks → log.
- Runs locally against the dev data stores, and in the prod Lambda.
- CI tests every change and deploys the service on merge to `main`.
- A smoke test proves the deployed service works end to end in prod.

### Non-goals (v1)

- `GET /api/sources`. Design.md marks it optional; the UI can link sources from each reply's citations.
- The `casual` and `sarcastic` styles (Design.md: "Later"). `style` is accepted from the start, so cached cards never need rebuilding.
- Streaming, user accounts, a review queue for cache writes.
- Any public launch step: the UI, the real Turnstile site key in a page, launch licence terms.

### Anti-goals (a failure even if it works)

- A reply that states a number or claim not in the answer card, or cites a source that wasn't retrieved.
- A reply that insults or mocks the commenter.
- Any LLM call made before Turnstile, the rate limit and the length cap have passed.
- Secrets in environment variables, logs or the repo; personal details in committed files.

## Approaches considered

| | Approach | Trade-off | |
|---|---|---|---|
| **A** | **Plain Lambda handler, no web framework.** `handler.py` reads the function URL event and routes the one route to plain functions; request checks are small dataclasses. A ~30-line local runner on the standard library's `http.server` feeds the same handler | We write our own request validation and error replies (~50 lines). No new dependencies; small package; short cold starts | **Chosen** |
| B | FastAPI + Mangum adapter | Validation and API docs for free, `uvicorn` locally. Adds four packages to vet, one compiled for arm64; adds ~0.3–0.5 s per cold start. Pays off only with many routes | |
| C | Lambda container image | Needs ECR and a different Terraform setup; the Lambda is already a zip | Ruled out |

Chosen by you: **A**, and **"keep things as simple as possible for v1"**. Plan 03 stops at **deployed, not public**.

## Design

### Request flow

```
POST /api/chat
  │ 1. parse + validate body          → 400 on bad JSON / unknown style or platform
  │ 2. length cap (MAX_COMMENT_CHARS) → 400
  │ 3. Turnstile siteverify           → 403
  │ 4. rate limit (minute + day)      → 429
  ▼
Classify LLM ──not a sceptical climate claim──► 200 { reply: <fixed polite message>, citations: [], fallacy: null, cached: false }
  │ claim, cards_category, tone
  ▼
embed claim ─► cache query (top 1) ──distance ≤ threshold──► answer card (cached: true)
  │ miss
  ▼
sources query (top 5) ─► Facts LLM ─► answer card ─► citation check ─fail─► 502
                                          │ pass
                                          └─► write to cache
  ▼
Reply LLM ─► reply checks (source ids ⊆ card's; every number in the card) ─fail─► retry once ─► 502
  ▼
log item ─► 200 { reply, citations, fallacy, cached }
```

The length cap runs before Turnstile because it's free and needs no network call; Design.md's rule is that Turnstile runs before the rate limit, the cache and any LLM, which still holds.

### Calls I made (check these)

- **Cache lookup, then source search only on a miss**, one after the other. Design.md runs them in parallel. Sequential is simpler, makes no wasted query on a hit, and costs about 0.2 s on a miss. Revisit only if measured latency misses the 4–6 s budget.
- **Haiku's hidden reasoning.** Haiku 5.5 thinks for about 300 tokens before answering, so Design.md's `max_tokens` (~150 / 500 / 200) would return empty replies. Phase 0 checks whether OpenRouter's `reasoning` setting can turn it off for these calls. If it can, use Design.md's limits; if not, use 1024 or more and record the extra cost (about +$0.00015 per call).
- **Structured output** via OpenRouter's JSON-schema `response_format` for Classify and Facts, if Phase 0 confirms Haiku 5.5 and the fallback support it there; otherwise a JSON-only prompt plus parsing with one retry.
- **Fallback model** through OpenRouter's `models: [primary, fallback]` on every chat call, with `provider.data_collection: deny` as for embeddings.
- **Prod smoke test without Turnstile:** the handler also accepts a **direct Lambda invoke** event `{"smoke": "<comment>"}` and runs it through the full pipeline from step 5 on. Only IAM principals can invoke the function directly (the function URL is locked to CloudFront, and function URL events always carry `requestContext.http`, so a public request can't produce this event). CI checks the public path returns 403 without a token; you run the full-pipeline invoke with your admin profile.
- **Licence filter is a setting, off for v1.** `EXCLUDED_LICENCES` (comma-separated, default empty) adds a `licence` `$nin` filter to the sources query. The launch decision stays open until plan 04 and becomes a one-line config change.
- **Logs keep the comment and a hashed user id, never the IP.** Each log item stores the comment, claim, CARDS category, cache hit, outcome, per-call model, tokens and cost, latency, and `user_hash`, with `expires_at` from `LOG_TTL_DAYS`. The raw IP appears only in the rate-limit keys, which expire within a day.
  - **Why:** to group requests by user and see whether a few users generate most of the traffic (e.g. one user making 90% of requests).
  - **How:** `user_hash = HMAC-SHA256(key, "<YYYY-MM>|<ip>")`, hex, first 16 characters. A plain hash isn't enough: the IPv4 space is small enough to reverse it by brute force. Putting the month in the input means ids group a user's requests within a calendar month but don't link across months, which suits monthly concentration checks and keeps the data closer to anonymous.
  - **Caveat:** an IP is a network, not a person. Mobile carriers and offices share IPs, and one person changes networks, so this measures concentration by network. That's good enough to spot one heavy source.
  - **The key is a new secret:** SSM `/climate-chat/prod/log-hash-key` (and `dev`), created in `Infrastructure/bootstrap/ssm.tf` and set with `put-secrets.sh`; the app stack adds it to `ssm_parameters`, which grants the Lambda read access and passes `LOG_HASH_KEY_PARAM`. Locally it's `LOG_HASH_KEY` in `.env`. This needs a bootstrap apply (local) and an app apply (CI on merge), each with the usual two confirmations.
  - Checking concentration is a DynamoDB scan grouped by `user_hash`; a small report command is out of scope for v1.
- **Rate limit:** one DynamoDB `UpdateItem` per window (`ip#<ip>#m#<minute>`, `ip#<ip>#d#<day>`) with `ADD count :1` and a condition `count < limit`; a failed condition is a 429. The IP comes from `CLIENT_IP_HEADER` with the port stripped (IPv4 and IPv6). Locally, with no header, the IP is `local`.
- **Turnstile** via `urllib.request` POST to Cloudflare's `siteverify`, so no HTTP library is added. The secret comes from SSM in Lambda (`TURNSTILE_SECRET_PARAM`) and from `.env` locally (Cloudflare's always-pass test secret is already there).
- **Secrets** are read from SSM on first use and cached in memory for 5 minutes (Design.md); locally from `.env`.
- **Error replies** are JSON `{ "error": "<code>", "message": "<text>" }`. A spent OpenRouter key (402) gives 503 "can't answer right now"; an upstream failure gives 502.
- **Packaging:** `pdfplumber` and `tiktoken` move to an `ingest` dependency group, which stays in uv's default groups so `uv sync` and the ingestion runbook don't change. The build uses `uv export --no-default-groups` and installs the arm64 / Python 3.14 manylinux wheels into a zip, with a one-line `handler.py` at the zip root importing `climate_chat.service`. Terraform's `handler.handler` stays as it is, so packaging needs no apply.
- **CI:** a new `.github/workflows/service.yml`. Pull requests run `ruff` and `pytest`; a push to `main` touching `src/**`, `pyproject.toml`, `uv.lock` or the workflow also builds and deploys (`update-function-code`, wait, then the 403 check). It uses the existing deploy role and secrets.
- **Not-a-claim reply:** a comment that Classify finds isn't a climate-sceptic claim returns 200 with a fixed message, so the UI handles one success shape.

### Code layout

```
src/climate_chat/
  config.py            # + service settings (tables, model ids, limits, SSM names, EXCLUDED_LICENCES)
  openrouter.py        # + ChatClient: chat completions with fallback, routing, usage/cost
  service/
    __init__.py        # handler(event, context): routing, errors, smoke event
    api.py             # request/response dataclasses and validation
    guards.py          # Turnstile, rate limit, client IP
    pipeline.py        # classify → cache → search → facts → reply, as one function
    prompts.py         # the three prompts and JSON schemas
    checks.py          # citation check, reply source-id and number checks
    cache.py           # answer-card read/write on response-cache
    logs.py            # log item
    local.py           # python -m climate_chat.service.local: http.server on :8000
tests/service/         # unit tests with fakes; no network
eval/replies.toml      # ~10 sample comments for a hand-reviewed end-to-end run
```

### Testing

- **Unit tests** for every module, with fake LLM, vector, DynamoDB and Turnstile clients (extending `tests/fakes.py`). The checks in `checks.py` get the most cases: numbers written differently ("1.5", "1.5°C", "1,000"), missing and extra source ids.
- **Retrieval regression:** the 20 myths in `eval/retrieval_myths.toml` go through the service's own embed-and-search code against the dev index; all 20 must still find an expected source. Marked as a live test and skipped unless asked for, so CI stays offline.
- **Reply review:** `eval/replies.toml` (about 10 real-looking comments across the five CARDS categories, casual and hostile, plus two non-claims) run end to end against dev. Results go in a report for you to read; this is a judgement check, not a pass/fail test.
- **Cache threshold:** chosen in Phase 0/1 by embedding paraphrases of a few myths (casual, formal, emoji) and picking a cosine distance that matches paraphrases without merging different claims. Recorded in Plan.md.

### Left to the builder

Exact prompt wording; the JSON schemas' field details beyond Design.md's answer card; how `Settings` is split between ingestion and service; the number-matching regex; log item key shape (`pk`/`sk`); the eval report format.

## Out of scope

- `GET /api/sources`, the `casual` and `sarcastic` styles, streaming.
- The Solid UI and the Turnstile widget (plan 04), and therefore the first public request.
- Deciding which licences may be quoted at launch (a setting is built; the decision is plan 04's).
- Raising the Lambda concurrency quota.
